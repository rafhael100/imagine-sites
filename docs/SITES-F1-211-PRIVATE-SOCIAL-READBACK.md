# F1-211 — Conferir cartão social após gravar o pacote privado

O motor já gera texto social opcional, mostra sua simulação no revisor (F1-210) e exporta a versão para um conjunto canônico de quatro arquivos (F1-209). A F1-211 fecha o ciclo ao **ler novamente o HTML armazenado** e conferir sua identidade contra a página sintética esperada.

SyntheticPrivateSocialCardReadbackV1 recebe apenas o inventário canônico de quatro arquivos e um SiteBrief esperado. Ele exige o resultado de SyntheticPrivateDraftVerifier::verifyBytes, confere que a revisão é pendente, o digest SHA-256 corresponde ao renderizador e os indicadores publishable/officialClientAcceptance permanecem false. Metadados ativados geram um cartão após a inspeção independente dos sete elementos Open Graph/Twitter; metadados desligados não fabricam nenhum cartão. Os métodos de autorização para publicar, aceitar, enviar CRM, buscar mídia e compartilhar permanecem false.

O comando CLI `sites:inspect-social-fixture` aceita somente as opções do catálogo finito de produto, tema, ordem, paleta, menu e social (on/off). É executável exclusivamente em PHP CLI + APP_ENV=testing + GitHub Actions + SITES_F211_SOCIAL_READBACK=1. Ele só inspeciona um pacote F1-205 **já existente** sob um nome de diretório fixo; não recebe caminhos arbitrários, clientes, URL, dados livres ou credenciais. O comando primeiro valida diretório, symlinks, hard links e os quatro arquivos e depois lê/valida novamente os bytes. Não é uma leitura atômica `openat`, nem modelo para arquivos hostis de produção.

Testes PHP 8.3/8.4 avaliam 24 variantes de pacotes em memória, com tentativas de troca de organização/layout, adulteração do HTML, manifesto falso ou arquivo adicional. Testes Laravel exportam oito pacotes de disco, conferem a inspeção, adulteração, link simbólico, falta de flags e parâmetros inválidos. Tudo permanece sintético e não publicável, sem cliente, rede social, CRM operacional, VPS, deploy ou custo adicional. OP01/OP02/OP04 e os dez gates de produção seguem bloqueados.
